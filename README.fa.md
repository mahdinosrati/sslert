# راهنمای قدم‌به‌قدم SSLert

[English README](README.md) · [مخزن پروژه](https://github.com/mahdinosrati/sslert)

SSLert ابزاری برای پایش تاریخ انقضای گواهی TLS/SSL و ثبت دامنه است که روی سیستم یا سرور خودتان اجرا می‌کنید. این ابزار گواهی صادر یا تمدید نمی‌کند؛ زمان باقی‌مانده را بررسی می‌کند و از طریق ایمیل، تلگرام، Slack، Webhook یا ntfy هشدار می‌دهد.

این راهنما بر اساس کد مخزن در بازبینی `9905627` تهیه شده است. مسیر اصلی نصب، Docker Compose است و دستورهای مشترک را می‌توانید در ترمینال لینوکس، macOS یا PowerShell ویندوز اجرا کنید. قسمت‌های وابسته به سیستم‌عامل جدا مشخص شده‌اند.

## ۱. پیش‌نیازها را آماده کنید

- Git برای دریافت پروژه.
- Docker Engine به همراه Compose v2 در لینوکس، یا Docker Desktop با کانتینرهای Linux در ویندوز و macOS.
- دسترسی اینترنت برای دریافت imageها و بسته‌های npm، و دسترسی شبکه از کانتینر به دامنه‌ها و سرویس‌های ارسال هشدار.
- یک دامنهٔ عمومی برای پایش، مانند دامنهٔ وب‌سایت خودتان.

نصب ابزارها را بررسی کنید:

```sh
git --version
docker --version
docker compose version
docker info
```

اگر دستور آخر نمی‌تواند به Docker متصل شود، ابتدا Docker Desktop یا سرویس Docker را اجرا کنید. برای روش Docker نیازی به نصب Node.js روی میزبان نیست.

## ۲. پروژه را دریافت کنید

```sh
git clone https://github.com/mahdinosrati/sslert.git
cd sslert
```

بقیهٔ دستورهای Docker این راهنما را از همین پوشه، کنار فایل `docker-compose.yml`، اجرا کنید.

## ۳. فایل تنظیمات را بسازید

در لینوکس یا macOS:

```sh
cp .env.example .env
```

در PowerShell ویندوز:

```powershell
Copy-Item .env.example .env
notepad .env
```

برای شروع بدون ایمیل، این مقدارها کافی است؛ سایر سطرهای فایل نمونه را نگه دارید:

```dotenv
RESEND_API_KEY=
ALERT_EMAIL_TO=
CHECK_INTERVAL=60
WEB_PORT=5173
```

با خالی بودن گیرنده، کانال ایمیل پیش‌فرض ساخته نمی‌شود. اگر گیرنده تنظیم شده باشد ولی کلید Resend خالی باشد، ارسال ایمیل به ثبت پیام در لاگ تبدیل می‌شود؛ این به معنی ارسال واقعی ایمیل نیست. تلگرام و سایر کانال‌ها مستقل از Resend هستند.

| تنظیم | کاربرد در Compose فعلی |
| --- | --- |
| `WEB_PORT` | پورت دسترسی به داشبورد روی میزبان؛ پیش‌فرض `5173` |
| `CHECK_INTERVAL` | تنظیم زمان‌بندی بررسی؛ پیش‌فرض `60` دقیقه |
| `RESEND_API_KEY` | کلید Resend برای ارسال واقعی ایمیل |
| `ALERT_EMAIL_TO` | گیرندهٔ پیش‌فرض ایمیل دامنه‌ها |
| `ALERT_EMAIL_FROM` | فرستندهٔ ایمیل روی دامنهٔ تأییدشده در Resend |

**نکتهٔ زمان‌بندی:** برنامه از cron استفاده می‌کند. مقدار `60` یعنی ابتدای هر ساعت، نه دقیقاً ۶۰ دقیقه پس از اضافه‌کردن دامنه. برای شروع همان `60` را نگه دارید. در کد فعلی، مقادیری مثل `90` یا `1440` به اجرای ساعتی تبدیل می‌شوند؛ همهٔ اعداد به فاصلهٔ زمانی دقیق تبدیل نمی‌شوند.

**نکتهٔ تنظیمات Docker:** وجود یک متغیر در `.env` به‌تنهایی به معنی ورود آن به کانتینر نیست. Compose فعلی تنها متغیرهای مشخص‌شده در بخش `environment` را منتقل می‌کند؛ مثلاً برای تغییر `LOG_LEVEL` یا `RATE_LIMIT_PER_MINUTE` باید آن‌ها را به `services.api.environment` نیز اضافه کنید. مسیر دیتابیس و پورت داخلی در Compose فعلی به‌ترتیب روی `/app/data/sslert.db` و `3000` ثابت هستند.

## ۴. سرویس‌ها را اجرا کنید

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 api web
```

ساخت نخستین image ممکن است چند دقیقه طول بکشد. در نهایت سرویس‌های `api` و `web` باید بالا باشند و healthcheck آن‌ها موفق شود. سپس [داشبورد محلی](http://localhost:5173) را باز کنید. اگر `WEB_PORT` را تغییر داده‌اید، همان پورت را در نشانی وارد کنید.

معماری اجرا: مرورگر به nginx در سرویس `web` وصل می‌شود؛ درخواست‌های `/api/` به سرویس داخلی `api:3000` می‌روند. دیتابیس SQLite در volume با نام منطقی `sslert-data` نگهداری می‌شود.

## ۵. توکن بسازید و وارد شوید

در image فعلی، فایل‌های کامپایل‌شده در `/app/dist` قرار دارند. برای ساخت توکن از همین فایل‌ها استفاده کنید:

```sh
docker compose exec --user 10001:10001 api node /app/dist/cli/tokens.js create --label admin
```

توکن چاپ‌شده را همان لحظه در جای امن ذخیره کنید؛ مقدار اصلی فقط یک‌بار نمایش داده می‌شود.

1. [صفحهٔ ورود](http://localhost:5173/login) را باز کنید.
2. توکن را در کادر **API token** قرار دهید.
3. روی **Sign in** کلیک کنید.
4. پس از تأیید توکن، داشبورد نمایش داده می‌شود.

راهنمای انگلیسی قدیمی به Settings و دستور `npm run token:create` داخل کانتینر اشاره می‌کند؛ در image فعلی، اسکریپت‌های npm ریشه و فایل‌های TypeScript موردنیاز آن روش موجود نیستند. دستور `node` بالا با ساختار Dockerfile فعلی هماهنگ است.

فهرست توکن‌ها:

```sh
docker compose exec --user 10001:10001 api node /app/dist/cli/tokens.js list
```

برای باطل‌کردن یک توکن، شناسهٔ واقعی آن را به‌جای `3` بنویسید:

```sh
docker compose exec --user 10001:10001 api node /app/dist/cli/tokens.js revoke --id 3
```

اگر توکن گم شد، توکن جدید بسازید و توکن قبلی را باطل کنید. فعال‌کردن `AUTH_DISABLED` راه‌حل مناسبی برای فراموشی توکن نیست.

## ۶. اولین دامنه را اضافه کنید

### انتخاب زبان فارسی

زبان پیش‌فرض پنل انگلیسی است. از فهرست زبان در صفحهٔ ورود یا نوار بالای پنل، **فارسی** را انتخاب کنید. انتخاب شما در مرورگر ذخیره می‌شود و با بارگذاری دوباره باقی می‌ماند. برای بازگشت، **English** را انتخاب کنید.

در حالت فارسی، چیدمان راست‌به‌چپ، فونت وزیرِ همراه پروژه، اعداد فارسی و تاریخ‌های نمایشی شمسی فعال می‌شوند. دامنه‌ها، توکن‌ها و مقادیر فنی تغییر نمی‌کنند. فیلترهای تاریخ گزارش فعالیت‌ها همچنان تاریخ میلادی می‌گیرند و مرز روز را بر اساس UTC محاسبه می‌کنند. زبان پیام‌های ایمیل و تلگرام و لاگ سرور با این انتخاب تغییر نمی‌کند.

### ثبت دامنه

1. در داشبورد گزینهٔ افزودن دامنه را انتخاب کنید.
2. در **Hostname** فقط نام میزبان، مثلاً `example.com`، را وارد کنید؛ بدون `https://`، مسیر یا شمارهٔ پورت.
3. **Port** را برای HTTPS معمول روی `443` بگذارید. پورت `8443` نیز به‌صورت پیش‌فرض مجاز است.
4. روی **Add & Check Now** کلیک کنید.
5. پس از پایان بررسی، روی دامنه کلیک کنید تا جزئیات گواهی، انقضای ثبت دامنه و تاریخچهٔ بررسی‌ها را ببینید.
6. برای بررسی دستی بعدی، از **Check Now** استفاده کنید.

هر نام میزبان را جدا ثبت کنید؛ گواهی `example.com` ممکن است با `www.example.com` متفاوت باشد. آدرس‌های خصوصی و loopback به‌صورت پیش‌فرض مسدودند. تاریخ ثبت دامنه از RDAP و در صورت نیاز WHOIS دریافت می‌شود؛ نبود این اطلاعات لزوماً به معنی خرابی گواهی TLS نیست.

## ۷. کانال‌های هشدار را تنظیم کنید

در صفحهٔ جزئیات هر دامنه، بخش **Alert Channels** را باز کنید، کانال موردنظر را انتخاب کنید، فیلدهای آن را پر کنید و **Save** را بزنید. تنظیمات کانال‌های هر دامنه مستقل است.

### ایمیل با Resend

1. در حساب Resend، دامنهٔ فرستنده را تأیید و یک API key ایجاد کنید.
2. این مقدارها را در `.env` قرار دهید و نمونه‌ها را با اطلاعات واقعی جایگزین کنید:

```dotenv
RESEND_API_KEY=replace-with-your-resend-api-key
ALERT_EMAIL_FROM=sslert@your-domain.com
ALERT_EMAIL_TO=admin@your-domain.com
```

3. برای اعمال تغییر متغیرها اجرا کنید:

```sh
docker compose up -d
```

4. گیرندهٔ عمومی یک کانال ایمیل پیش‌فرض ایجاد می‌کند. برای تنظیم اختصاصی دامنه، کانال **Email (Resend)** و فیلدهای **To** و **From** را تنظیم کنید.

### تلگرام

1. با BotFather یک ربات بسازید و توکن آن را دریافت کنید.
2. گفت‌وگو با ربات را شروع کنید، یا آن را به گروه مقصد اضافه کنید و دسترسی لازم برای ارسال پیام بدهید.
3. شناسهٔ عددی گفت‌وگوی مقصد را از اطلاعات به‌روزرسانی‌های ربات دریافت کنید؛ نام کاربری جایگزین مطمئنی برای این شناسه نیست.
4. در کانال **Telegram**، مقدارهای **Bot Token** و **Chat ID** را وارد و ذخیره کنید.

### سایر کانال‌ها

| کانال | فیلدهای رابط کاربری | کار لازم |
| --- | --- | --- |
| Generic Webhook | `URL` و `Signing secret` اختیاری | نشانی HTTPS دریافت‌کنندهٔ POST JSON را وارد کنید؛ کلید امضا در صورت استفاده حداقل ۱۶ کاراکتر باشد. |
| Slack | `Incoming Webhook URL` | نشانی وب‌هوک متصل به کانال مقصد را وارد کنید. |
| ntfy | `Topic` و `Server` اختیاری | یک topic انتخاب کنید و در کلاینت ntfy مشترک همان topic شوید؛ سرور پیش‌فرض `https://ntfy.sh` است. |

### چه زمانی باید منتظر هشدار بود؟

| روز باقی‌مانده | سطح |
| --- | --- |
| بیشتر از ۳۰ روز | بدون هشدار انقضا |
| بیشتر از ۷ تا ۳۰ روز | `warning` |
| بیشتر از ۱ تا ۷ روز | `urgent` |
| بیشتر از صفر تا ۱ روز | `critical` |
| صفر یا کمتر | `emergency` |

هشدار گواهی (`cert`) و ثبت دامنه (`domain`) مستقل هستند. برای ترکیب یکسان دامنه، منبع، کانال و سطح، تلاش تکراری ارسال در پنجرهٔ ۲۴ساعته محدود می‌شود. بنابراین **Check Now** دکمهٔ ارسال آزمایشی بدون شرط نیست. برای بررسی مسیر ارسال، دامنه‌ای تحت کنترل خودتان که واقعاً در محدودهٔ هشدار است را بررسی و سپس تاریخچهٔ هشدارها و لاگ API را مشاهده کنید:

```sh
docker compose logs --tail=100 api
```

## ۸. API را استفاده کنید

درخواست‌های عملیاتی `/api/*` به هدر `Authorization: Bearer ...` نیاز دارند. در Bash، توکن را بدون نمایش هنگام تایپ بخوانید:

```bash
read -rsp 'API token: ' SSLERT_TOKEN
printf '\n'
curl -H "Authorization: Bearer $SSLERT_TOKEN" http://localhost:5173/api/domains
unset SSLERT_TOKEN
```

در PowerShell:

```powershell
$sslertCredential = Get-Credential -UserName sslert -Message 'Enter the API token as the password'
$sslertHeaders = @{ Authorization = 'Bearer ' + $sslertCredential.GetNetworkCredential().Password }
Invoke-RestMethod -Uri 'http://localhost:5173/api/domains' -Headers $sslertHeaders
Remove-Variable sslertCredential, sslertHeaders
```

| روش | مسیر | کاربرد |
| --- | --- | --- |
| `GET` | `/api/domains` | فهرست دامنه‌ها |
| `POST` | `/api/domains` | افزودن با بدنهٔ JSON مانند `{"hostname":"example.com","port":443}` |
| `GET` | `/api/domains/1` | جزئیات دامنه با شناسهٔ ۱ |
| `POST` | `/api/domains/1/check` | بررسی دستی دامنه با شناسهٔ ۱ |
| `GET` | `/api/alerts` | تاریخچهٔ هشدارها |
| `GET` | `/api/config` | تنظیمات مؤثر زمان‌بندی و وضعیت پیکربندی Resend |

شناسهٔ `1` را با شناسهٔ واقعی دامنه عوض کنید. مشخصات عمومی API از [OpenAPI JSON](http://localhost:5173/api/openapi.json) در دسترس است. مسیر `/api/docs` نیز در API تعریف شده، اما رابط Swagger ممکن است پشت CSP فعلی nginx نتواند منابع خارجی‌اش را بارگیری کند؛ در این حالت فایل JSON را در ابزار سازگار با OpenAPI وارد کنید.

## ۹. نسخهٔ پشتیبان بگیرید

از دیتابیس در حال اجرا با کپی سادهٔ فایل SQLite بکاپ نگیرید؛ ابزار پروژه snapshot می‌سازد. خروجی را در مسیر قابل‌نوشتن `/app/data` قرار دهید:

```sh
docker compose exec --user 10001:10001 api node /app/dist/cli/backup.js create /app/data/sslert-backup.tar.gz --db-path /app/data/sslert.db
docker compose cp api:/app/data/sslert-backup.tar.gz ./sslert-backup.tar.gz
```

برای هر نوبت، نام تازه‌ای مانند `sslert-backup-2026-10-28.tar.gz` انتخاب کنید تا بکاپ قبلی بازنویسی نشود. نسخهٔ خروجی را خارج از این مخزن و ترجیحاً روی فضای ذخیره‌سازی دیگری نگه دارید.

Compose فعلی فایل `.env` میزبان را داخل کانتینر mount نمی‌کند؛ پس این دستور از تنظیمات واقعی میزبان بکاپ نمی‌گیرد. `.env` را جداگانه و امن نگه دارید. حذف اسرار فقط روی نسخهٔ متنی `.env` اعمال می‌شود؛ دیتابیس آرشیو می‌تواند تنظیمات حساس کانال‌ها را داشته باشد. فایل بکاپ را در GitHub قرار ندهید.

### بازیابی بکاپ

بازیابی، اطلاعات فعلی را با اطلاعات زمان بکاپ جایگزین می‌کند. ابتدا از وضعیت فعلی یک بکاپ جدا بگیرید. دستورهای زیر فرض می‌کنند فایل موردنظر برای بازیابی به نام `restore-input.tar.gz` کنار Compose قرار دارد و سرویس API هنوز در حال اجراست:

```sh
docker compose cp ./restore-input.tar.gz api:/app/data/restore-input.tar.gz
docker compose stop web api
docker compose run --rm --no-deps --user 10001:10001 --entrypoint node api /app/dist/cli/backup.js restore /app/data/restore-input.tar.gz --db-path /app/data/sslert.db --env-path /app/data/.env --yes
docker compose up -d
docker compose ps
```

سرویس‌ها هنگام جایگزینی دیتابیس متوقف می‌شوند. `--entrypoint node` لازم است، چون entrypoint عادی این image همیشه API را اجرا می‌کند و فرمان CLI را جایگزین آن نمی‌کند. گزینهٔ `--yes` تأیید تعاملی بازیابی را رد می‌کند؛ فقط پس از انتخاب بکاپ درست آن را اجرا کنید. اگر مرحلهٔ بازیابی خطا داد، پیش از بالا آوردن سرویس‌ها علت را رفع کنید.

ابزار یک نسخه از دیتابیس قبلی با پسوند `.pre-restore` و یک فایل تنظیمات پالایش‌شده با نام `/app/data/.env.restored` می‌نویسد. تنظیمات واقعی `.env` میزبان را خودکار جایگزین نمی‌کند. پس از بازیابی، ورود، فهرست دامنه‌ها و یک بررسی دستی را امتحان کنید؛ توکن‌های ساخته‌شده پس از زمان بکاپ در دیتابیس بازیابی‌شده وجود ندارند.

## ۱۰. توقف و به‌روزرسانی

توقف موقت و شروع دوباره:

```sh
docker compose stop
docker compose start
```

برای به‌روزرسانی ابتدا بکاپ بگیرید، سپس:

```sh
git pull --ff-only
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 api web
```

اگر Git به دلیل تغییرات محلی متوقف شد، ابتدا آن تغییرات را بررسی کنید؛ آن‌ها را با reset اجباری حذف نکنید. دستور `docker compose down` بدون `-v` volume داده را نگه می‌دارد، اما `docker compose down -v` آن را حذف می‌کند و برای به‌روزرسانی عادی مناسب نیست.

## ۱۱. نکات استقرار روی سرور

- Compose پیش‌فرض HTTP ارائه می‌دهد. برای استفادهٔ اینترنتی، یک reverse proxy با HTTPS جلوی داشبورد قرار دهید؛ این پروژه HTTPS داشبورد را خودکار راه‌اندازی نمی‌کند.
- نگاشت پورت پیش‌فرض روی همهٔ رابط‌های میزبان منتشر می‌شود. اگر reverse proxy روی همان میزبان دارید، می‌توانید نگاشت سرویس `web` را به `127.0.0.1:${WEB_PORT:-5173}:80` محدود کنید.
- توکن در `localStorage` مرورگر ذخیره می‌شود؛ از مرورگر مشترک برای مدیریت استفاده نکنید و توکن را در فایل‌های عمومی نگذارید.
- پورت API را مستقیماً روی میزبان منتشر نکنید و احراز هویت را برای محیط واقعی غیرفعال نکنید.
- `/health` روی پورت وب فقط سلامت nginx را نشان می‌دهد. برای بررسی آمادگی API و دیتابیس، دستور زیر را اجرا کنید:

```sh
docker compose exec api node -e "fetch('http://localhost:3000/health/ready').then(r=>r.json()).then(console.log)"
```

- برای Prometheus، endpoint داخلی `http://api:3000/metrics` را از همان شبکهٔ Compose scrape کنید. nginx فعلی `/metrics` را به API proxy نمی‌کند. داشبورد آمادهٔ Grafana در [این فایل](packages/api/grafana/sslert-dashboard.json) است.

## ۱۲. رفع خطاهای رایج

| مشکل | اقدام پیشنهادی |
| --- | --- |
| `docker` یا `docker compose` پیدا نمی‌شود | نصب Docker و Compose v2 و بازکردن ترمینال جدید را بررسی کنید. |
| پورت `5173` اشغال است | در `.env` مقدار `WEB_PORT=8080` بگذارید، `docker compose up -d` را اجرا و پورت جدید را باز کنید. |
| خطای `401` هنگام ورود | توکن را بدون فاصلهٔ اضافی وارد کنید؛ با دستور فهرست توکن‌ها، وجود و انقضای آن را بررسی کنید. |
| `502` یا API ناسالم | خروجی `docker compose ps` و لاگ `api` را بررسی کنید؛ سلامت `/health` وب به‌تنهایی کافی نیست. |
| `Missing script` یا `tsx: not found` داخل image | از دستورهای `node /app/dist/cli/...` همین راهنما استفاده کنید. |
| `Invalid hostname` | فقط نام میزبان عمومی بدهید؛ پروتکل، مسیر و پورت را از فیلد Hostname حذف کنید. |
| خطای اتصال یا TLS | DNS، پورت مقصد، اعتبار گواهی و دسترسی خروجی کانتینر را بررسی کنید. |
| تاریخ انقضای دامنه خالی است | نتیجهٔ RDAP/WHOIS و دسترسی شبکه را بررسی کنید؛ اطلاعات همهٔ دامنه‌ها در دسترس نیست. |
| هشدار دریافت نمی‌شود | آستانهٔ انقضا، فعال‌بودن کانال، اطلاعات گیرنده، لاگ ارسال و محدودیت تکرار ۲۴ساعته را بررسی کنید. |
| `readonly database` | ابتدا `docker compose restart api` را امتحان کنید تا entrypoint مالکیت volume را اصلاح کند؛ volume را حذف نکنید. |
| بکاپ با `Read-only file system` شکست می‌خورد | خروجی آرشیو و مسیر `--env-path` هنگام بازیابی باید در مسیر قابل‌نوشتن، مانند `/app/data`، باشند. |

## ۱۳. اجرای توسعه بدون Docker — اختیاری

برای توسعه، Node.js 22 و npm را نصب کنید. بستهٔ `better-sqlite3` وابستگی native دارد و بسته به سیستم ممکن است ابزار کامپایل لازم شود. دستورهای زیر برای Bash روی لینوکس، macOS یا WSL نوشته شده‌اند؛ مسیر اصلی راهنمای ویندوز همان Docker است.

در ریشهٔ مخزن:

```bash
npm ci
```

در ترمینال اول:

```bash
export DATABASE_PATH="$PWD/data/sslert.db"
export CHECK_INTERVAL=60
npm run dev:api
```

در ترمینال دوم، باز هم از ریشهٔ مخزن:

```bash
export DATABASE_PATH="$PWD/data/sslert.db"
npm run token:create --workspace=@sslert/api -- --label admin
npm run dev:web
```

هر دو فرایند باید به همان مسیر مطلق دیتابیس اشاره کنند. اسکریپت‌های فعلی `.env` ریشه را خودکار بارگیری نمی‌کنند؛ متغیرهای موردنیاز مانند تنظیمات ایمیل را در محیط فرایند API تنظیم کنید. داشبورد توسعه روی پورت `5173` است و درخواست‌های API را به `localhost:3000` می‌فرستد.

برای بررسی تغییرات کد:

```sh
npm test
npm run typecheck
```
